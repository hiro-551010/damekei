# 削除・廃止ポリシー

- 機能削除は必ずドキュメント更新を伴う。
- deprecated状態を経由してから削除する。

## DB マイグレーション戦略（Expand / Contract）

DB スキーマの変更は **Expand → Migrate → Contract** の3段階で行う。一度にカラム/テーブルを削除しない。

| フェーズ | 内容 | 例 |
|---|---|---|
| **Expand** | 新しいカラム/テーブルを追加する。既存構造は残す | カラム名変更 → 新カラムを追加し、旧カラムはそのまま残す |
| **Migrate** | データを新構造に移行する。アプリケーションコードを新構造に切り替える | 旧カラムの値を新カラムにコピーし、コードの参照先を新カラムに変更する |
| **Contract** | 旧構造を削除する。新構造のみになる | 旧カラムを削除する |

- Expand と Contract は**別々のマイグレーションファイル・別々の PR** で行う。
- Contract は、Expand + Migrate がリリースされ安定稼働を確認してから実施する。
- マイグレーションファイルは Context 単位で管理する（`docs/00_governance/directory-structure.md` 参照）。
